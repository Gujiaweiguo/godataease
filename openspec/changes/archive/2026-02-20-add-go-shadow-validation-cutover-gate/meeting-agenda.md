## 会议议程

### 1. 项目背景与迁移概述（5分钟）

**主讲人**：Engineering Manager 或指定技术负责人

**内容**：
- 迁移目标与范围
- 当前架构状态
- Java 后端状态（只读备份）
- Go 后端状态（主线）

**关键点**：
- 16 个核心模块已迁移
- 139 条 API 路由兼容
- 前端已适配完成

---

### 2. 质量门禁验证结果（10分钟）

**主讲人**：技术负责人

**验证项清单**：

| 检查项 | 状态 | 结果 |
|--------|------|------|
| 单元测试 | ✅ | `make test` 通过 |
| 构建 | ✅ | 32MB 二进制 |
| Lint | ✅ | 57 项低优先级 |
| Docker | ✅ | 镜像构建成功 |
| Docker Compose | ✅ | 配置验证通过 |

**讨论点**：
- Lint 警告是否可接受？
- 是否有遗漏的测试场景？

---

### 3. Shadow 验证结果回顾（10分钟）

**主讲人**：Observability Engineer

**关键指标**：

| 指标 | 阈值 | 实际值 | 状态 |
|------|------|--------|------|
| Mismatch Rate | < 1% | 0.30% | ✅ PASS |
| Critical Security Incidents | = 0 | 0 | ✅ PASS |
| Sev-1 Regressions | = 0 | 0 | ✅ PASS |
| Sev-2 Regressions | = 0 | 0 | ✅ PASS |

**Shadow 窗口**：
- 持续时间：4 小时
- 检查点：4/4 通过
- 最终决策：GO

**讨论点**：
- Mismatch 的具体原因是什么？
- 是否有潜在风险未覆盖？

---

### 4. 风险评估与回滚方案（5分钟）

**主讲人**：Release Manager

**风险等级**：中等

**已知风险**：

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 未覆盖的边缘场景 | 低 | 48h 观察期 |
| 回滚时间 | 低 | RTO < 5 分钟 |
| 数据不一致 | 低 | 事务保护 |

**回滚触发条件**：
1. Mismatch rate >= 1%
2. 任何 critical 安全事件
3. 任何 Sev-1/Sev-2 回归
4. 错误率 > 5% 持续 5 分钟

**回滚时间**：
- Dry-run 演练：0 秒（通过）
- 真实演练：PENDING（需凭证）

**待决事项**：
- ⚠️ 真实回滚演练未完成（需要生产网关凭证）

**讨论点**：
- 是否可以在获得凭证后立即执行切换？
- 还是需要等待真实演练完成后再切换？

---

### 5. Q&A 与审批签署（5分钟）

**主持人**：Engineering Manager

**决策问题**：

1. **技术就绪**：基于以上数据，Go 后端是否已准备好接管生产流量？
   - [ ] 是
   - [ ] 否（需说明原因）

2. **风险接受**：团队是否接受当前风险等级？
   - [ ] 是
   - [ ] 否（需说明原因）

3. **切换时间**：推荐的切换窗口是？
   - 日期：________
   - 时间：________

4. **真实演练**：何时执行真实回滚演练？
   - 日期：________
   - 时间：________

**签署环节**：
- Engineering Manager 签署：________
- Release Manager 签署：________
- Observability Engineer 签署：________

---

## 决策输出

### 如果 GO

1. 确认切换窗口
2. 执行真实回滚演练（如未完成）
3. 发送切换通知
4. 执行生产切换

### 如果 No-Go

1. 记录阻塞原因
2. 制定解除阻塞计划
3. 安排下次审批会议
